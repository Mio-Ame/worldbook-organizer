- **只搬不改**：搬走的声明逐字节相同（唯一改动是在需要跨模块可见的声明前加 `export`、以及 hub 里的 import/re-export 行）。

## 4. 与 AGENTS.md 相关的拆分风险点（必读）

1. **原生 `change` 事件（AGENTS.md #1）**：目标书下拉的"写值后派发原生 `change`"逻辑整体留在 hub（`attachGroupedSelectControl` 未被搬），本轮没有触碰；但注意 `desktop-extras.js` 里 `liveDialogSelectFor` 的**同名实现在 diagnostics 侧**仍被引用——如果以后有人改了 hub 里那份，记得两边口径要一致（本轮是纯搬移，行为未变）。
2. **行属性自愈（#2）**：`repairNativeRowActionAttrs` 已搬进 `src/native-filter/dropdown-order.js`，三个调用点仍在 hub。**改动前的必查项**：该函数的幂等性依赖"每次列表重建后再调一次"，搬家不影响，但**不要**把它挪进只在打开下拉时执行的路径。
3. **禁止在 pointerdown 改布局（#3）**：`restoreForNative` 相关逻辑（`v2.35.126` 的修复）完整留在 hub，未被搬。拆分本身不改变事件时序，但**子模块顶层不能出现副作用**——本轮四个子模块全部只有声明（脚本已核对：hub 与子模块顶层没有可执行的副作用语句），所以模块求值顺序不会提前触发任何 DOM 操作。
4. **下拉顺序口径（#4）**：`enforceSelect2GroupOrder` / `enforceShellGroupOrder` 搬到了 `dropdown-order.js`；调用点在 hub 的 `layoutGlobalGroupRows` / `syncResults` / `enhanceOpenGlobalDropdown`。**风险**：这条规则要求"每次 sync 后幂等校正"，如果以后在子模块里新增调用点，务必保持"重建 → 校正"的顺序。
5. **分页误判（#5）**：`describePager` / `rowSetFingerprint` 已搬进 `diagnostics.js`，诊断报告里的 `pager` 字段由此生成；搬移不改输出，但**改动诊断字段名会同时影响两条真机判读规则**（行数不变≠没变化）。
6. **手机可导出诊断（#6）**：`wboBuildDiagnostic('compact')` 与三项菜单在 hub（`enhanceCustomDropdownPopover` 邻域），未搬；`diagnostics.js` 只提供数据构造函数。检查时请确认 **`compact` 输出字段集合没有因搬移减少**（本轮无字段改动）。
7. **样式覆盖脚本（本轮新增的通用风险）**：`style.css` 拆成八片后，任何新增规则必须落在**正确的分片且不改变片间顺序**；跨片覆盖靠 `src/style-manifest.js` 的数组顺序，改顺序=改级联结果。`style.css` 自身只剩 `@import`，**不要**再往里写规则（否则会跑到所有分片之前）。
8. **测试拆分后的 globals 传递**：`core-prelude.mjs` 现在是唯一一份 `../src/core.js` import 清单；新增测试要用的符号必须在那里补 import + re-export，否则会得到 `ReferenceError`（不会静默通过）。
9. **E2E 前的浏览器残留**：拆分后每个阶段都跑过 E2E，每次开跑前都先删 `本轮材料/**/.edge-profile-*`；不删会出现 `EPERM` 与 5s 超时假红（AGENTS.md 第 7 条）。

## 5. 副作用顺序（拆分后实测核定）

1. `index.js` 顶层 import 求值顺序未变（仍是 `core → host → native-filter → panel → entry-groups/lifecycle → feature-gate → content-scroll → panel-manager → import-organizer → style-manifest`；`style-manifest.js` 是纯数据模块，无副作用）。
2. `native-filter.js` 新增的四个子模块 import 语句排在原有 import 之后：子模块**只有声明**，因此它们的求值不会改变任何时机；`hub ↔ 子模块` 的循环导入在 ESM 下是"声明先绑定、赋值后使用"，函数在调用时（`init()` 之后）才读状态，实测 `import('./src/native-filter.js')` 通过。
3. `boot()` → `init()` 的副作用顺序未改（其中 `ensureFreshStylesheet()` 现在一次追加 8 个 `<link>`，紧跟在同一位置调用；仍是"先挂新、全部 load 后再摘旧"，避免闪样式）。
4. `onDisable()` 仍按 `assetRoot` 前缀清理样式 `<link>`，分片文件的 URL 前缀相同，所以能一起清掉。
